# SPEC：AI 领域知识库问答系统

## 背景与目标

AI 论文、课程讲义和项目文档分散在 PDF、网页与 Markdown 中，用户需要一个能回答问题并给出证据的本地优先工具。目标是让首次用户在 2 分钟内完成启动和提问，并能判断答案是否来自资料。

## 范围

包含文档导入、文本清洗和切分、SQLite FTS5/关键词混合检索、证据片段展示、离线回答、可选 OpenAI 兼容模型适配、HTTP API、MCP search 工具、健康检查和统计信息。不包含交叉红队与多租户权限。

## 可测验收标准

| ID | 验收标准 |
|---|---|
| A1 | `py -3 server.py` 启动后 `/api/health` 返回 `ok:true` |
| A2 | 启动后至少有 1 个示例文档和 1 个片段 |
| A3 | 对“什么是 RAG”返回非空回答，且每个引用含 title/source/snippet |
| A4 | 空库或未知问题返回明确“没有找到足够证据”的拒答 |
| A5 | `/api/ingest` 重复 source 会更新文档而不是产生重复来源 |
| A6 | 页面展示 offline/llm 模式，不虚构模型调用 |
| A7 | 无 API 密钥时所有核心功能可用；PDF 在安装 pypdf 后可导入 |
| A8 | 可运行测试和 hook，README 给出复现命令 |

## 成功指标

离线检索的证据命中率、引用覆盖率、拒答正确率和 P95 响应时间由 `tests/test_app.py` 与人工检查记录；先保证引用覆盖率 100%，再优化模型质量。

## 非目标与风险

FTS5/关键词方案解释性强但不等价于向量语义检索；后续可替换 `query()`，保持 API 和引用结构不变。模型服务网络错误会安全回退到离线回答。
