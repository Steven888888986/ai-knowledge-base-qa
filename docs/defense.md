# AI 领域知识库问答系统答辩稿

建议用时：约 6–8 分钟。第 11 页小组姓名与分工请由成员据实补充。

## 第 1 页｜AI 领域知识库问答系统

各位老师好，我们汇报的项目是 AI 领域知识库问答系统。它面向课程讲义、论文和项目笔记等资料，目标是让用户既能获得回答，也能回到原文核验依据。系统尽量在本机运行，减少对云端模型密钥的依赖。成员姓名与个人分工请由小组根据实际贡献补充。

## 第 2 页｜需求与成功标准

AI 学习资料常分布在多种文件和网页中，直接询问通用模型时，答案未必能对应到用户手里的资料。因此我们把目标拆为九项验收：服务健康、示例资料、可追溯引用、无证据拒答、重复来源更新、显示实际回答模式、无密钥时可用、可复现测试，以及模型下载校验与异常回退。最后一项要求核对下载模型的 SHA-256，并在模型不可用或引用无效时回退为可核验原文。它们把“能回答”扩展成“能解释答案从哪里来”。

## 第 3 页｜从资料导入到带证据的回答

用户导入 Markdown、HTML 或 TXT；安装 pypdf 后也能处理 PDF。系统清理文本、按片段切分并保存来源和页码。提问时，检索层找出相关证据，再交给本地模型生成；如果证据不足，系统会明确拒答。最后页面同时展示回答、模式、引用来源和原文片段。重复导入同一个 source 会更新资料，而不是堆出重复来源。

## 第 4 页｜系统架构与模块边界

页面由静态 HTML、JavaScript 和 CSS 构成；server.py 提供本地 HTTP API。ingestion.py 负责导入、解析和切分；retrieval.py 在 Python 中计算 BM25，并组合 BGE 向量检索与 RRF 排名；app.py 处理证据判断、回答、拒答和引用。SQLite 保存文档、片段、向量与元数据，不使用 FTS5。模型服务通过本机的 OpenAI 兼容接口调用。

## 第 5 页｜混合检索、证据约束与拒答

系统并行执行 BM25 词项检索和 BGE 稠密向量检索，再用 Reciprocal Rank Fusion 合并排序，当前常数为 60。回答前会检查证据相似度及问题词项重叠。每条引用保留来源、片段编号和页码，方便回到原文。如果模型生成结果没有有效引用编号，会回退到可核验的原文摘录。需要强调，引用能追溯来源，但不等于答案中的每个事实主张都已独立核实。

## 第 6 页｜本地预训练模型与运行方式

生成模型使用 Qwen2.5-1.5B-Instruct 的 Q4_K_M 量化版本，约 1.117 GB；向量模型使用 BGE-small-zh-v1.5 的 Q8_0 版本，512 维。两者由固定版本 llama.cpp 在 CPU 上运行，不需要云端 API 密钥。项目记录的一次本地生成样例约 2.3 秒，实际响应速度会随电脑配置变化。模型下载脚本会校验文件 SHA-256。模型来源与许可证信息已列入本页演讲者备注。

## 第 7 页｜现场演示

现场先启动模型服务和网页，检查健康接口显示模型状态正常。我们输入“什么是 RAG？”，查看模型回答、模式徽标和引用卡片，再展开来源与片段，核对原文。随后输入“明天的天气如何？”。知识库中没有天气资料，所以系统应该拒答，而不是编造天气预报。演示的具体命令见 `docs/demo-script.md`。

## 第 8 页｜评测设计与提交前验证

项目自建了十二篇 AI 知识短文，其中二十四道可回答问题带有人工标注来源与证据，另有八道库外问题用于评估拒答。离线混合检索的 Recall@3 为 100%，证据引用准确率 100%，引文可追溯率 100%，正确拒答率 100%，误拒率 0%，P95 为 30.04 毫秒。这个 P95 来自关闭生成模型的离线评测，不含模型生成耗时。另一次配置本地 LLM 的实测包含生成耗时：BM25、向量和混合模式的 Recall@3 分别为 100%、95.8%、100%，分别生成 24/24、23/24、24/24 个可回答题的答案，证据引用准确率均为 100%，P95 分别为 2502.92、3208.22、3879.21 毫秒；三种模式的引用可追溯率和正确拒答率均为 100%，误拒率分别为 0%、4.2%、0%。两组结果属于不同评测口径。十四项单测全部通过；另对 Qwen 的 K01、K03、K07 三题做定向实推，均返回有效引用。该集合是开发集，不是独立测试或生产基准；引用准确率不代表所有生成主张都已证实。

## 第 9 页｜工程流程：AI 协作工具与自动检查

项目包含 kb-research 与 verify 两类技能指南，分别约束来源检索和行为核验；MCP 通过只读工具 search_knowledge_base 暴露检索结果；reviewer agent 检查回答主张与引用是否对应。preflight hook 和 GitHub Actions 会运行检查、测试和评测。自动化负责提供证据与发现问题，最后的事实判断仍由小组负责。本次按要求不包含交叉红队。

## 第 10 页｜当前限制与后续验证

目前知识集和问题集规模有限，真实资料覆盖还需要扩展。可追溯引用不能替代对生成内容逐条核对；小模型的回答质量与 CPU 延迟也受硬件限制。PDF 导入依赖 pypdf。项目将 Windows 中文路径下的子进程输出和重复 source 更新检索问题纳入回归用例，并已通过当前单测；后续仍要扩大真实资料复测和复查演示中的每条引用。

## 第 11 页｜五人小组分工

这一页保留五个成员填写栏。请成员分别填写姓名、负责模块、实际贡献和可核验材料，例如代码提交、文档、演示或评测记录。这里不预填个人姓名和贡献，以免将未确认的信息当成事实。

## 第 12 页｜结论

本项目把本地资料、混合检索、预训练模型和引用展示接成一个可运行的问答流程。用户能看到答案依赖的来源与片段，也能在证据不足时得到明确拒答。我们希望把知识库问答从“给出一段文字”推进到“给出可核验的回答”。谢谢大家，欢迎提问。
