# 网站实时问答指标

页面“问答质量统计”在每次 HTTP 问答完成后自动更新。召回率与引用准确率明确标为**自动估算**，默认由已配置的本地 Qwen 评估；模型关闭、不可用或输出格式无效时使用标明方法的词项规则回退。拒答率直接统计实际响应。三种检索方式的问答共同累计，当前不按检索方式分组。

纯数字输入（如 `2`）属于内容查找，展示全部包含该数字串的文档及原文片段。它不生成问答、自动评估或历史记录，因此不改变这里的分子、分母和核验次数；查找结果没有“本次问答核验”。此前已经保存的数字问答记录作为历史保留，不追溯删除。

纯算式（如 `1+1`）仍是问答：资料未明确提供算式及结果时拒答、引用为空，拒答会正常计入累计统计。它与纯数字内容查找的口径不同。

## 使用步骤

1. 正常提问，系统生成回答、自动评估并保存记录后，一起返回回答和三项指标。自动评估会增加一次模型调用的等待时间。
2. 查看卡片下的分子/分母和总问答数。新样本计入不保证百分比改变，例如连续两次都命中来源仍为 100%，计数从 1/1 变为 2/2。拒答且无引用的记录不会凭空增加引用分母。
3. 如需纠正，点击“人工核验 / 修正”。窗口显示自动结论、评估方法、参考来源和范围；人工表单不默认把自动判断算成人工核验。
4. 人工判断是否可回答，并选择正确来源（可选未召回的文档或手动填写来源）。逐条引用可保留自动结果，也可改为正确或错误。保存后立即重算，重复修改不增加问答或引用数量。
5. “问答记录与核验”展示最近 50 条，累计统计包含全部记录。刷新及重启后保留。

## 计算口径

| 指标 | 分子 | 分母 | 判断依据 |
|---|---|---|---|
| 召回率 Recall@3（自动估算） | 前 3 个检索片段命中至少一个评估相关来源的问题数 | 评估为可回答的问题数 | 有人工判断则用人工来源，否则用自动评估 |
| 引用准确率（自动估算） | 判断为正确的引用数 | 已判断的实际引用数 | 逐条人工判断优先，其余保留自动判断 |
| 拒答率 | 响应 refused=true 的问答数 | 所有已完成并记录的 HTTP 问答数 | 实际响应，与人工或自动评估独立 |

没有分母时接口返回 null，页面显示横线或“无样本”，不编造 0% 或 100%。仅尚无任何评估的旧记录显示待评估。多个正确来源命中一个即计一次命中；这是来源命中口径，不表示召回了所有相关片段。人工核验次数与模型/规则估算次数可能重叠，因为二者分别保存。

自动评估是近似值，不是经过人工标注的真实准确率。Qwen 1.5B 也可能误判，且与生成器共用模型会产生相关偏差；词项规则更无法可靠判断语义支持。引用来源存在、文字匹配只是必要检查，不等于答案全部正确。拒答率也不等于“正确拒答率”，并非越高越好。

## 自动评估与范围

`auto_eval.py` 将问题、回答、候选证据与引用交给模型，要求结构化 JSON，校验来源标签、引用编号和布尔判断。引用须先与保存的检索证据一致，再检查其是否支持对应回答。问题是否可回答独立判断，不能因系统已经拒答就自动排除召回失败。

评估证据池不只取回答使用的前 3 项。小库可使用全库片段，大库受上下文限制选择独立候选池；保存 scope，窗口展示范围：

- `full-library`：完整提供当时的全部知识片段。
- `candidate-pool`：只提供有限候选或截断的片段，不能宣称全库真实召回率。
- `saved-retrieval`：旧记录补评仅使用当次保存的检索/引用快照。不能恢复当时漏检的资料，这类召回估算可能偏高。

自动结果保留方法 local-model / lexical-fallback、模型、简短说明、范围、时间和耗时，便于复核。输入文档作为待分析数据，不作为模型指令。

为适配本地模型的上下文，模型最多读取问题前 250 字，以及每条引用中选出的 200 字主张和 240 字原文；长问题或包含多项主张的回答可能因截取遗漏信息。判断只是所选文本上的估算，需要时仍应查看完整原文人工修正。

## 存储、接口与旧记录

`metrics.py` 在现有 SQLite 的 query_events 表中保存问题、时间、原回答、检索证据、自动评估 auto_review 和人工判断 review。升级自动添加字段，保留旧数据。更新/删除文档不会改写过去的回答快照；数据库被 Git 忽略，不上传用户问答历史。

- `GET /api/metrics`：累计分子/分母、比例、模型/规则估算次数、人工核验次数及无评估记录数。
- `GET /api/history`：最近 50 条快照、auto_review 与 review。
- `POST /api/history/{id}/review`：保存或替换 `{answerable, expected_sources, citation_verdicts}`。引用键必须是实际引用编号；省略表示不作人工覆盖。
- `POST /api/query`：问答完成时返回 query_id、auto_review 和更新后的 metrics；空问题不记录。纯数字查找返回 mode=lookup、lookup.matches、query_id=null、auto_review=null 及当前 metrics，不新增记录。每份匹配文档的 passages 列出全部命中上下文，原 snippet/chunk_id/page 字段保留为第一段信息。

补评已保存且没有自动结果的记录：

```powershell
py -3 scripts/backfill_metrics.py
```

补评不创建问答、保留人工判断，重复执行不会重复计数。建议操作前备份数据库。功能启用前没有保存的问答无法补造。终端直接调用 app.answer()、离线评测和 MCP 检索均不进入网站累计统计。
