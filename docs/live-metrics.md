# 网站实时问答指标

页面“问答质量统计”记录启用该功能后的真实 HTTP 问答。旧版本未保存问答快照，因此不补造历史数据。统计按本地知识库累计，混合、BM25、向量三种检索方式产生的问答均计入；当前界面不按检索方式分别筛选。

## 使用步骤

1. 正常提问，完成后自动更新总问答数和拒答率。
2. 点击“核验本次回答”，先判断当时知识库中是否有足够资料回答。
3. 如果有答案，选择一个或多个正确来源。列表包含当前知识库和当次检索/引用来源；可手动输入未列出的来源，因此未召回的正确资料也能计入评测。
4. 对照原回答与原文，将每条引用标为正确、错误或待核验；保存后两个质量指标立即更新。
5. 从“问答记录与核验”重新打开历史记录可以修改。历史列表展示最近50条，统计包含全部记录。已提交核验的记录仍可能有待核验引用，引用卡上的分母只包含实际判定过的引用。

## 计算口径

| 指标 | 分子 | 分母 | 何时更新 |
|---|---|---|---|
| 召回率 Recall@3 | 当次检索前3个片段命中至少一个人工标注正确来源的问题数 | 人工标注为可回答的问题数 | 保存或修改核验 |
| 引用准确率 | 人工标为正确的引用数 | 已被判定正确或错误的引用总数 | 保存或修改核验 |
| 拒答率 | 响应 `refused=true` 的问答数 | 所有已完成并记录的 HTTP 问答数 | 每次完成问答 |

没有分母时接口返回 `null`，页面显示“待核验”或“—”。未核验的问题与引用不当作正确或错误。每条记录只保存一份当前核验，修改时替换，避免重复计数。Recall@3 沿用离线报告的来源命中口径；多个正确来源中命中一个即算命中，不表示已检索出所有相关资料。

在线引用准确率由用户判断引用是否支持对应回答；离线评测脚本则检查人工标注的来源和证据字符串，两种指标依据不同。拒答率不判断该不该拒答，不等于离线报告中的“正确拒答率”，也不是越高越好。用户核验的准确程度会影响在线质量指标。

## 存储与接口

`metrics.py` 在现有 `data/kb.sqlite3` 中建立 `query_events` 表，保存提问、时间、原回答、检索结果、引用及核验。数据库被 Git 忽略，问答内容不会上传 GitHub。刷新页面、重启服务不会清空；更新或删除文档也不会改变当次证据快照。原回答内是否提到文件名由提问与知识库内容决定。

- `GET /api/metrics`：累计统计、小数比例和分子/分母。
- `GET /api/history`：最近50条问答快照及当前核验。
- `POST /api/history/{id}/review`：保存或替换 `{answerable, expected_sources, citation_verdicts}`。`citation_verdicts` 以本次实际引用编号为键、布尔判断为值；未核验编号省略。
- `POST /api/query`：原响应新增 `query_id` 和 `metrics`，空提问返回400且不计数。

终端直接调用 `app.answer()`、离线开发集评测和 MCP 检索不进入网站累计统计。新功能启用前已经完成的问答不会自动回填。

## 验证

后端回归覆盖空样本、未核验排除、部分引用判断、前3项边界、修改核验替换、无效标注、删除文档后的快照、服务重启持久化以及离线评测隔离。

```powershell
py -3 docs/evidence/live-metrics-ui.py
```
