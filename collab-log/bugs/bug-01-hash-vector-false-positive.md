# BUG-01：离线哈希向量碰撞导致旧问题命中新文档

- 发现方式：AI 辅助实现后的回归测试
- 严重性：中（可能展示与问题无关的证据）
- 状态：已修复
- 引入来源：AI 辅助实现的初版候选门控逻辑；本档案属于本次 AI 开发会话的缺陷记录，不归属于某位组员。
- 回归用例：`IsolatedAppTest.test_replace_source_does_not_leave_old_chunks`

## 复现

```python
app.index_document("概念", "one.md", "旧内容 蓝色三角形")
app.index_document("概念更新", "one.md", "新内容 红色圆形")
app.query("蓝色三角形")
```

修复前，结果错误地返回已更新文档的片段 `新内容 红色圆形`，BM25 为 `0.0`、哈希向量 cosine 为 `0.401106`。测试断言 `self.assertFalse(app.query("蓝色三角形"))` 失败，因为离线词项哈希向量的碰撞被当成了语义命中。

## 原因与修复

哈希向量只是离线词项特征，不具备预训练向量模型的语义判别能力；原排序阈值允许它独立产生候选。检索层现在要求哈希向量候选同时满足词项支持，回答层也检查问题词覆盖；更新同一来源后，旧问题不再命中新内容。真实 BGE 向量使用独立阈值。

## 复盘假设与证据

复盘时需区分两种可能：旧片段未删除，或新片段被错误命中。已保存的错误结果内容为“新内容 红色圆形”，BM25 为 0，而哈希 cosine 为 0.401106，支持第二种解释。回归测试同时断言旧词无结果、新词可命中以及文档数为 1，分别约束检索门控和来源更新。此处是事后依据现有证据整理的分析，不冒充当时逐字会话。

## 沉淀

`AGENTS.md` 增加“离线哈希向量不是语义模型”及候选与证据分别验证的约定；`verify` skill 要求核对来源与片段，不只看结果格式。没有保存的首次修复 prompt、被否定方案或 token 消耗不予补造。

## 验证

`py -3 tests/test_app.py` 中回归用例验证旧词无结果、新词可命中且来源只保留一份。离线评测中混合检索 Recall@3 为 100%，库外问题正确拒答率为 100%；详见 `eval/report.md`。这些结果只适用于该项目编写的开发集。
